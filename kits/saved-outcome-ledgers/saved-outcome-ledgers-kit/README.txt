SAVED OUTCOME LEDGERS / BOUNDED RECOUNT

Extract the whole ZIP. In saved-outcome-ledgers-kit run:
    python -I -B replay.py
Python 3.9+; standard library only. No solver, network, installation or output
file writes. Exit zero with passed=true means the retained bytes and finite
parsing checks pass, not that historical labels have been proved.

What is checked
- Six sparse cases, each occupying two physical lines.
- 112 resolver records: 31 VERIFIED labels and 81 non-pair labels.
- Five saved horizons and nine odd-cutoff propagation markers.
- Eight literal carry-oracle fields; four malformed parser controls reject.

The original oracle path was unavailable at library review. The retained bytes
match the earlier catalogue pin. This portable kit does not inspect original
workspace paths: original_presence_checked=false and original_present=null.
It does not reconstruct missing experiments, certificate proofs, probability
laws or encoding conventions. A propagation ok marker is not SAT. A saved
UNSAT label is not a checked certificate. VERIFIED inventory labels are not
additional discoveries on top of the library's separate 31-pair replay.

Format guides
Eight carry-oracle fields: preserve a failed probe without inventing its domain
Headerless two-column key/value table; eight unique keys. False is literal Boolean text, not a missing value.
The retained 192 bytes match their pinned public hash, but the original path is unavailable. Characteristic, generator, carry convention and mismatch metric are missing; neither dimension nor failed probes establish a universal impossibility result.

Six sparse-result cases in twelve physical lines
Each four-field descriptor (job, steps, input support, expanded support) is followed by a separate tab-prefixed UNSATISFIABLE line. No header. Supports are comma-separated integer indices.
These are historical labels under the original encoding, not checked proof certificates or a complete sparse-family closure. Retain the false-wall article's encoding corrections.

A found-file name is not a collision: read the 112-row resolver inventory
Five tab-separated columns: page, source, kind, n, verdict. Final # count line is a trailer, not a 113th record. Non-pair rows have an empty n field.
This parser checks inventory labels only. The existing separate 31-pair replay provides arithmetic verification. Do not add these 31 labels to that replay as additional discoveries or execute source paths listed in the table.

Five saved pinning horizons, not five SAT boundaries
Three headerless tab-separated fields: S42 support label, R42, horizon=<integer>. Preserve input-word and expanded-word support separately.
A horizon label does not specify all cutoffs tried, prove monotonicity or supply a numerical collision. The associated article distinguishes historical and later runner predicates.

Nine odd cutoffs: update-all success is only a propagation marker
Two tab-separated fields: fix_to <integer> and literal update all... failed!/ok!. No header; the tested descending grid is 31,29,27,25,23,21,19,17,15.
The table is not a complete solver decision, does not contain the separate two-bit-condition guard, and does not test even cutoffs. Never interpolate missing cutoffs as tested outcomes.
